# 数据约定

## 线路帧

每个 UDP 数据报是一份 UTF-8 JSON；payload 为 Base64，摘要均为 SHA256。
`index` 从 0 开始，`count` 是总片数。`device` 与 `boot` 确定启动范围，
16 位 `sequence` 按该范围内的连续观察解释回绕；完整负载按片号串联。

帧字段：`device`、`boot`、`sequence`、`index`、`count`、`part_sha256`、
`group_sha256`、`payload`。任一字段缺失、取值越界、Base64 非法或
`part_sha256` 不符，报文在协议边界被拒绝并按原因计数，不进入组装状态机。
`count` 超过设备策略 `max_count`（以及硬上限 1024）的超大组同样在边界拒绝。

## 序号与启动代次

- 序号差按模 65536 解释，结果落在 (-32768, 32767]；差值恰为 32768 是
  无法区分前进与回退的歧义点，必须停止并请求新的启动代次。
- 源端仅重传最近 `retention_groups`（16）组，乱序跨度至多
  `max_reorder_span`（32）组。无论序号向前还是向后，差距超过该跨度都
  意味着连续位置无法由乱序解释，整个代次置为失败，等待新 `boot`，
  不能凭接收时刻猜测测量周期，也不能把同序号的不同周期混合。
- 设备以新 `boot` 重启时，旧代次中尚未组齐的组立即放弃；已发布、
  已放弃的结论不受晚到片影响。

## 组的归组与隔离

归组键是 `(device, boot, sequence)`，不能仅按序号归组（序号会回绕、
设备重启也从 0 开始）。

- 同片重传且内容一致：幂等，重复计数但不改变状态。
- 同片内容冲突、`count` 改变、`group_sha256` 改变：整组隔离（abandoned），
  永不发布。
- 全部片齐全后再对串联负载计算 SHA256，与 `group_sha256` 一致才发布；
  不符则隔离。重复收齐只发布一次。

## 资源上界与缺片重取

- 每设备缓存组数受 `max_groups` 限制，到上界时淘汰最久未活动的未完成组；
  已发布组不参与淘汰。
- 每个未完成组有 `group_ttl`，超时由 sweep 放弃，离线设备不能永久占缓存。
- 缺片重取只对落在源端暂存窗口（最近 `retention_groups` 组）内的组发起；
  每组有 `refetch_max_attempts` 次数上限和总时长上限，源端返回空
  （暂存失效）后标记耗尽，不再请求，交由 TTL 淘汰。
- 来源地址与设备策略不匹配、未知 `boot`（固定代次时）的报文一律拒绝。

## 进程恢复

状态目录（默认 `state/`）：

- `groups/<device>/...json`：每组一份，含状态（assembling/published/
  abandoned）、放弃原因与全部已到片负载，原子覆盖写。
- `records/<device>/...json`：发布记录，完整负载与摘要，是交付下游的契约。
- `sessions.json`：启动代次会话与序号高水位。

恢复后三种状态分别归位：未组齐的组继续组装，已发布的不重复交付，
已放弃的组不会被晚到片重新变成成功。

## 控制面

控制口与数据口分离。向控制口发送 `{"query":"status"}` 返回 JSON 快照：
计数器、会话状态、每组状态/缺片/剩余 TTL、协议错误分类、重取追踪。
`{"command":"reopen_boot","device":...}` 用于在外部确认后清除失败会话。

## 重取边界

`retrieval.RetransmitSource` 是可注入边界：测试用内存实现
（与 `source.Retention.missing` 同语义），生产用 `UdpRetransmit` 发
`{"request":"missing",...}` 并只接受目标地址的回应。设备暂存失效后
`missing` 返回空列表。
